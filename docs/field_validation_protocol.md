# 现场与标注验收协议

本项目是智能家居**仿真**平台。本协议规定了在把软件结果升级为真实设备、现场安全或节能结论前，必须保存和核验的可审计证据。

> 仿真测试、构建成功、模型连通性和 RAG 指标只能证明相应的软件行为；它们不是实体设备、现场安全或真实节能证据。

**RAG 检索关键词：** real device emergency stop rollback field validation（真实设备、急停、回滚、现场验收）。

## 证据层级与答辩表述

| 证据层级 | 可以表述 | 不可以表述 |
| --- | --- | --- |
| 软件仿真 | 多设备数字孪生闭环、可复现实验、算法在设定模型下的表现 | 真实全屋设备已部署、真实安全或节能效果 |
| 照明实体子系统 | 已测照明传感—决策—调光—反馈闭环 | 所有家居设备均完成实体控制 |
| 完整现场验收 | 满足本协议并通过对应现场实验的具体结论 | 超出设备、环境、时间范围的泛化结论 |

对于现有照明硬件实验，建议表述为“照明子系统已完成实体闭环验证”；全屋多设备平台仍应明确为仿真验证，除非其自身已有独立的现场证据。

## 语义标注裁决

存在多种合理动作粒度的任务，必须记录：任务 ID、原始指令、候选语义、裁决动作、裁决人、日期和理由。未裁决任务不得计入模型错误，也不得进入基准准确率分母。

例如“把书房窗帘打开一些”可能对应 `turn_on`，也可能对应包含开度参数的 `set_target`。研究者必须在版本化标注文件中选择并说明一种含义。

## 真实设备验收清单

在宣称真实设备控制、安全性或节能效果前，至少应保留：

1. 设备型号、固件、网关版本、驱动器与受控实体清单；
2. 隔离测试环境、回滚步骤、人工急停机制与故障注入记录；
3. 原始传感器读数、校准信息、时间同步方法与缺失数据处理规则；
4. 对照策略、预注册指标、采样窗口、负载/并发配置和原始日志清单；
5. 实验产物的 SHA-256 清单，以及可复现的分析脚本；
6. 适用范围：房间、设备数量、测试时段、天气/日照条件和受试者/操作者范围。

缺少任一关键项时，结果应表述为仿真、软件集成或探索性实体测试，而非可泛化的真实设备结论。

## 可执行验收入口

复制 `data/field_validation/field_validation_evidence.example.json` 并补全真实记录。在原始产物目录创建清单后执行：

```powershell
$env:ARTIFACT_SIGNING_KEY = '<从仓库外的密钥管理系统注入>'
.\backend\.venv\Scripts\python.exe scripts\verify_artifact_integrity.py create <原始产物目录> --require-signature
.\backend\.venv\Scripts\python.exe scripts\validate_field_validation_evidence.py <完成的证据文件.json>
```

只有校验器返回 `accepted: true`，且证据确实来自隔离的实体测试环境时，才具备提出对应真实设备结论的最低可审计条件。该校验器不产生现场数据，也不替代必要的真实设备、测量和人工安全审核。

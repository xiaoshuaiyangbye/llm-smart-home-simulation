# 论文论证链、创新性与证据边界

正式大论文题目：**《基于大语言模型智能体的智能家居系统研究》**。

本文档把项目的实现、实验和论文主张连接成一条可检查的论证链。机器可读事实源为
[`data/research/thesis_claims.json`](../data/research/thesis_claims.json)，校验命令为：

```powershell
.\backend\.venv\Scripts\python.exe scripts\validate_thesis_claims.py --require-generated-evidence
```

校验通过只表示每个研究问题都有机制、对照、指标、证据、允许结论、禁止结论和下一步；
`submission_ready=false` 当前只表示独立人工语义标注审查尚未完成，不能把软件实验完整误写成标签有效性已经获得外部确认。

## 结论先行

项目现在已经形成完整的**论文论证结构**，RQ1、RQ3 和 RQ5 的软件实验也已闭合；外部研究证据仅剩两名真实独立标注者与分歧裁决。人工审查完成并重生成指标后，还要把最终图表、原始记录和提交版本冻结到签名 manifest；后者是投稿打包门禁，不是新的实验效应证据。
最适合的定位是设计科学/系统研究论文：研究重点不是“首次用 LLM 控制智能家居”，而是：

> 面向动态住宅状态，设计一个可审计的自治智能家居数字孪生，使慢速 LLM 规划不会覆盖最新住户意图，
> 反思记忆不会绕过显式反馈和安全边界，实验结果能够区分 mock、真实模型、软件仿真和实体现场证据。

当前创新性主要属于**应用特定的系统机制和证据方法创新**，不是新的基础模型、优化算法或并发控制理论。
如果论文写成“多智能体全面优于单智能体”“个性化提高所有指标”或“真实家庭安全节能”，现有证据不支持。

## 一条完整的论文逻辑链

```mermaid
flowchart LR
    A["现实问题：LLM 规划慢、状态持续变化、偏好会累积"] --> B["研究缺口：旧计划覆盖新状态，反思可能越权，实验来源易混淆"]
    B --> C["方法：快照提交 + 受约束记忆 + 可干预多智能体 + 证据门禁"]
    C --> D["实现：数字孪生、自治服务、私有记忆、黑板轨迹、产物校验"]
    D --> E["对照：无门禁提交、单智能体、静态多智能体、规则语义"]
    E --> F["指标：过期提交、延迟、能耗、舒适度、效用、安全干预、语义准确性"]
    F --> G["证据：回归测试、消融、复现实验、长期运行、真实模型运行"]
    G --> H["边界：固定软件仿真，不外推真实住户、实体设备或总体性能"]
```

这条链的关键是“问题—机制—可证伪对照—指标—结果—边界”逐项对应。界面功能数量、Agent
角色数量或演示效果本身都不构成论文贡献。

## 当前结果应该怎样解释

### 个性化不是“所有指标都更好”

当前配对消融支持的是固定画像参与规划后的能耗—舒适度权衡：该方法在固定模拟任务中降低能耗并提高加权效用，
但舒适度下降。论文应同时报告各单项指标和权重，不能只选择 `weighted_utility` 得出全面优势。
现有区间是对固定任务簇的描述性不确定性，不是显著性检验。该实验使用预构造画像，没有运行
“反思→重复显式反馈→确认升格→`confirmed_experience`→后续规划”的形成链，因此效应不能归因于反馈门禁；
反馈门禁当前只有机制正确性证据。

### 多智能体普通任务尚无优势证据

`multi_agent_static` 在普通任务上的完成、舒适度、能耗、效用和满意度与 `single_agent` 相同。
这说明当前普通任务不能区分安全审查分支，而不是“多智能体已被证明无用”。三个不同机制的命名故障夹具能证明
审查分支确实改变并阻断了构造候选动作，并达到任务簇描述性区间阈值；仍不能推断故障发生率、总体安全或真实家庭安全。

### 真实模型表现是多指标权衡，不是全面优越

固定 digest 的 qwen3:8b 已完成 36 任务、3 次隔离重复，与规则语义基线共形成 216 条记录且运行成功率均为 100%；这里的“运行成功”只表示无 runtime error，不表示语义正确或任务完成。
覆盖率与准确率使用预注册的主重复（每组 n=36），其余两次重复用于稳定性。qwen 提高了意图准确率（+11.11 个百分点）、控制方向准确率（+50.00 个百分点）、设备 F1（+9.46 个百分点）和完成率（+2.78 个百分点），
但目标精确匹配降低 36.11 个百分点、目标范围 IoU 降低 12.66 个百分点，平均响应增加约 3.26 秒，能耗与占用房间舒适度也更差。
语义/计划精确重复稳定性为 91.67%/97.22%，低于规则基线的 100%/100%。因此可写“自然语言整体意图与控制方向改善，但参数控制、效率和稳定性存在代价”，不可写“LLM 全面优于规则系统”。

### 长期运行只支持本窗口稳定性

30 分钟测试支持单个隔离会话、本地 Docker 软件仿真在该窗口内无 API 错误、无持久化失败、无状态违规，
并捕捉到过期计划门禁行为。它不等于多日寿命、并发容量、真实设备耐久性或硬实时保证。

### 签名校验能力不等于当前产物已签名

仓库已经实现并回归测试 HMAC-SHA256 manifest 的创建、缺密钥拒绝、错误密钥拒绝和篡改检测。
当前论文引用的复现、个性化和长期运行产物尚未绑定经复验的签名 manifest，因此现在只能主张
“签名完整性能力已实现”，不能主张“当前图表和结果已经获得签名来源保证”。

| LLM + RAG + 多智能体 + 数字孪生集成 | 各组件及其组合已有大量先例 | “构建用于验证上述机制的可复现实验平台” | 是工程贡献，不应单独作为学术创新点 |

### 为什么不能把常见组件写成“首次”

- Generative Agents 已使用观察、规划、记忆和反思形成持续行为：<https://doi.org/10.1145/3586183.3606763>。
- Reflexion 已提出语言反思写入情节记忆并影响后续决策：<https://arxiv.org/abs/2303.11366>。
- HomeLLaMA 已研究本地、隐私保护和个性化智能家居：<https://arxiv.org/abs/2507.08878>。
- IoTGPT 已研究智能家居任务分解、记忆复用与个性化：<https://arxiv.org/abs/2601.04680>。
- SmartHouseOperator 已研究多智能体、能耗、舒适度和持久记忆：<https://doi.org/10.3390/app16041896>。
- AgentSense 已把 LLM Agent、模拟住宅和虚拟传感器用于数据生成：<https://doi.org/10.1609/aaai.v40i3.37169>。

以上仅是用于界定当前主张的代表性一手文献，不是具有检索式、数据库范围、纳排标准和质量评价的系统综述，
因此不能据此证明“文献中从未出现”。创新点必须落在已有组合没有回答的具体问题与可复核机制上。当前最有辨识度的是：
异步状态安全提交、用户确认门控的反思边界，以及把干预轨迹与结论边界共同机器化。

## 推荐的论文结构

1. **绪论**：从慢速非确定性 LLM 与持续变化住宅状态之间的冲突切入，提出 RQ1–RQ6。
2. **相关工作**：分别讨论智能家居 LLM、数字孪生与模拟 Agent、记忆/反思、多智能体安全、实验可复现性；明确不主张组件首次出现。
3. **问题形式化与系统边界**：定义状态、revision、偏好指纹、计划、提交前提、人工覆盖、证据等级。
4. **方法设计**：重点写快照提交协议；随后写受约束记忆闭环、中心编排干预轨迹和证据契约。
5. **系统实现**：FastAPI 运行时、数字孪生、RAG、Agent 黑板、私有记忆、日志与验证器。
6. **实验设计**：每个 RQ 单独列假设、对照、任务单位、指标、排除规则、失败处理和统计方法。
7. **实验结果**：分别呈现过期计划、个性化权衡、安全夹具、复现性、真实模型语义结果；不跨 RQ 混合结论。
8. **讨论与有效性威胁**：mock/real、任务代表性、固定模拟器、权重敏感性、夹具人工性、外部效度和真实设备缺失。
9. **结论**：只总结已获得证据的贡献，并把真实住户/设备验证留作外部工作。

## 大论文可用的贡献表述草案

在保留软件仿真边界并完成独立人工标签审查后，可使用以下句式：

1. 提出一种面向持续变化智能家居状态的乐观快照提交协议，将环境 revision、个性化偏好指纹和确定性
   `commit_id` 作为 LLM 计划执行前提，使过期计划能够被记录并拒绝。
2. 设计一种显式反馈门控的反思个性化机制，将用户确认经验限制为规划上下文，不允许反思自动修改关键控制目标或放宽安全约束；该机制的控制效用需要独立实验，不能由固定画像消融替代。
3. 构建一种证据感知的中心编排多智能体流程，将角色是否实际改变动作、指标适用性、模型来源和故障夹具来源保存在同一可审计产物中；最终论文产物仍需绑定并复验签名 manifest。
4. 实现可复现的智能家居数字孪生平台，并通过对照、消融、故障注入、长期运行和 fail-closed 校验评估上述机制。

以下句式当前禁止使用：

- “首次将 LLM / RAG / 多智能体 / 长期记忆用于智能家居”；
- “多智能体全面优于单智能体”；
- “个性化显著提高舒适度、满意度和节能”；
- “系统实现自我进化”；
- “系统已验证真实家庭安全和实际节能”。

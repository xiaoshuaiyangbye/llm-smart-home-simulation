# 持续改进闭环（Loop Engineering）

本项目的持续改进不是无边界的“自动修改”，而是可审计、可验证、可停止的工程闭环。

## 每轮流程

1. **发现**：只读检查 CI、测试报告、依赖审计、结构化服务日志和用户反馈。
2. **分类**：按安全、正确性、可靠性、体验、性能或文档分类，并为问题设定验收标准。
3. **实施**：每轮只处理一组能独立验证的改动；不提交密钥、不自动部署、不自动合并。
4. **验证**：执行后端测试、前端类型检查/构建；安全或并发改动必须补充相应回归测试。
5. **复盘**：将问题、最小修复、验证证据、研究边界、残余风险与下一步建议写入 `docs/improvement_backlog.md`。
6. **停止**：验收标准满足且不存在已证实的 P0/P1 回归时停止；需要产品、安全或现场负责人决策时，停止并等待人工授权。

## 保护栏

- 生产环境通过 `API_AUTH_TOKEN` 启用 API 鉴权；浏览器只获得 HTTP-only 会话 Cookie，密钥只保存在部署环境变量中。
- 每个 `X-Simulation-Session` 拥有隔离的仿真状态，单个会话内的修改按顺序执行。
- 自动化只能修改本地工作区；推送、部署、合并和删除数据必须人工授权。
- 每项“改进”必须有可重复的测试、构建或可观测证据，不能仅由模型自评决定。
- 软件质量门禁通过不等于现场实验完成；真实设备结论仍须满足 [field_validation_protocol.md](field_validation_protocol.md)。

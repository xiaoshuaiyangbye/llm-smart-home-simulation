# 改造闭环（Loop Engineering）

本项目的持续改造不是无边界的“自动自我修改”，而是一个可审计、可停止的工程闭环。

## 每轮流程

1. **发现**：读取 CI、测试报告、依赖审计、结构化服务日志和用户反馈。
2. **分类**：按安全、正确性、可靠性、体验、性能、文档分类，并为每项指定验收标准。
3. **实施**：每轮只处理可独立验证的一组改动；不提交密钥、不自动部署、不自动合并。
4. **验证**：执行后端测试、前端类型检查与构建；安全或并发改动必须补充回归测试。
5. **复盘**：把结果、证据、未解决风险和下一轮候选项写入 `docs/improvement_backlog.md`。
6. **停止**：当验收标准全部满足、没有 P0/P1 回归，或需要产品/安全负责人决定时停止并等待人工审批。

## 护栏

- 生产环境通过 `API_AUTH_TOKEN` 开启 API 鉴权；浏览器仅获得 HTTP-only 会话 Cookie，密钥只保存在部署环境变量中。
- 每个 `X-Simulation-Session` 拥有独立的仿真状态，单会话内的变更顺序执行。
- 自动化只能修改本地工作区；推送、部署、合并和删除数据都必须由人工授权。
- “改进”必须由可重复的测试、构建或可观测性证据证明，不能仅由模型自评决定。

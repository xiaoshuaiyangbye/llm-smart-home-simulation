# 运行控制契约

本文说明交互控制、持续自治、生活快速仿真和研究运行时如何共享或隔离状态。它是排查“页面显示、传感器感知和设备动作不一致”问题时的首要逻辑地图。

## 状态所有权

| 状态 | 唯一事实来源 | 写入入口 | 读取约束 |
| --- | --- | --- | --- |
| 房间占用与人物位置 | 住户级 `SmartHomeEnvironment` | `PUT /api/presence/current-room`、生活模拟事件 | 前端只投影后端确认状态；同步失败必须回滚 |
| 设备、环境、舒适度、能耗 | 住户级 `SmartHomeEnvironment` | 设备动作、环境设置、显式仿真步骤、自治或生活模拟 | `GET` 接口不得刷新天气或推进时间 |
| 仿真时钟 | `time_hour + time_minute` | 普通步骤、自治周期、生活模拟快照 | 短步骤必须累计，跨 24:00 正确回绕 |
| 用户画像、属性、反馈、反思 | 住户私有记忆 | 画像、属性和反馈接口；Reflection Agent | 不能由自治自行放宽安全规则或擅自改写关键偏好 |
| 自治生命周期 | `AutonomousRuntimeService` | 启动、停止、诊断 tick | `active + stopping` 表示周期仍在退出，不能当作已停止 |
| 生活快速仿真 | `LifeSimulationService` | 启动、tick、停止、回到今天 | 运行期间冻结外部写入口，避免两套时钟和策略争用 |
| 确定性研究运行 | 独立 `ResearchRuntime` | 研究运行和重放接口 | 不复用交互住户的可变轨迹；日志必须可重放 |

## 四条主链路

### 1. 人工设备控制

```text
前端/客户端 → API 校验与住户锁 → 设备模型 → 环境/传感器/舒适度/能耗重算
             → 注册 300 秒手动覆盖 → 返回后端确认状态
```

手动覆盖阻止持续自治马上反转用户刚做出的灯光、温控、风扇或窗户选择。

### 2. 自然语言控制

```text
用户指令 → Semantic Agent → RAG/Memory → Planning + Collaboration
         → Safety/Critic → 虚拟设备执行 → Feedback → Reflection → 私有经验
```

普通请求和 SSE 实时轨迹必须调用同一个 `TaskRunner`，区别只在于过程是否逐阶段流式发送。成功执行的动作同样注册手动覆盖。

### 3. 持续自治

```text
启动 → 短锁内推进时间并生成带 revision 的状态快照 → 传感器触发
     → 锁外 Semantic/RAG/Planning/Safety/Critic → 短锁内 revision/偏好指纹校验
     → 未变化则幂等 commit → Feedback/Reflection；已变化则拒绝旧计划并立即重规划
```

人员进入暗房间时另有一个有界照明 reflex：仅在自治已开启时作用于当前房间灯光，用于避免把基础照明响应绑定到 LLM 时延。它可观察、可记录、可被手动覆盖，且不能扩展为其他设备的规则捷径。

LLM 与多智能体规划不再长期占用住户锁，因此 presence 和人工操作可以先改变环境。提交前若环境 revision 或偏好指纹变化，旧计划以 `stale_snapshot_replan_required` 拒绝，不执行任何设备动作；动作批次包含确定性 `commit_id`，重复提交会被抑制。冷却只在成功提交后生效。失败会计入连续失败并允许下一周期重试；达到上限后服务自动停止。停止是“请求停止 → 等待当前周期退出 → 未激活”的两阶段状态机。

### 4. 生活快速仿真与研究运行

生活快速仿真是对住户状态的加速独占写入者，所以运行期间拒绝其他外部变更，并与持续自治互斥。研究运行时则使用独立状态、种子和日志，不应修改交互住户的环境或私有轨迹。

## 必须一直成立的不变量

1. 同一住户最多一个持续自治工作线程。
2. 同一时刻只能由持续自治或生活快速仿真中的一个推进交互住户状态。
3. 所有 `GET` 状态/健康接口均为纯读取。
4. 页面人物所在房间必须来自后端占用状态，不得用前端覆盖层伪造。
5. 失败动作不得进入重复触发冷却，也不得清零连续失败计数。
6. 停止请求未完成时，不得重置状态、启动生活模拟或启动第二个自治线程。
7. 研究运行、回放和指标不能把交互住户的隐藏历史当作实验初始条件。
8. 自治规划只能提交到生成该计划的环境 revision 和偏好指纹；过期计划不得执行。
9. 同一 `commit_id` 的动作批次最多提交一次。

## 当前边界

当前两阶段提交消除了 LLM 规划对住户锁的长时间占用，并能拒绝并发变化后的旧计划；`REAL_LLM_TIMEOUT_SECONDS` 仍限制单次模型调用。它不构成硬实时调度或真实设备事务：实体部署仍需持久优先事件队列、跨进程调度所有权、设备侧幂等确认、网络重试/回滚、超时降级演练和现场安全验证。

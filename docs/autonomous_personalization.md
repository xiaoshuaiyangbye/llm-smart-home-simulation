# 自治感知、私有记忆与反思学习

本模块把系统从“收到一次自然语言指令后执行一次”扩展为可选择开启的持续自治闭环：

```text
环境推进 → 传感器感知 → 个性化阈值判断 → 多智能体规划与安全审查
        → 虚拟设备执行 → 结果反馈 → 结构化反思 → 私有记忆更新
```

## 自治感知

“启用持续感知与自主决策”会启动后端常驻调度线程；前端仅负责启停和读取状态，关闭页面不会终止自治服务。默认每 5 秒执行一个周期，每周期推进 5 分钟软件仿真时间。周期和冷却参数会持久化，但后端进程重启后不会自动恢复设备控制权，必须由用户再次明确启动。

后端采用两层自治控制。第一层是仅在“自治已启用 + 人员进入房间 + 房间低照度”时执行的有界照明 reflex；它不调用 LLM，只允许控制当前房间的灯，动作会写入设备日志，并受手动覆盖约束。第二层是周期性的审慎决策，读取人员占用、温度、湿度、照度和设备运行状态，按照确定性优先级最多提出一个 Agent 控制任务：

1. 无人但仍有设备运行时，提出离家节能任务；
2. 照度低于个人目标的 75% 时，提出照明任务；
3. 占用房间温度越过个人温度与容差范围时，提出热舒适任务；
4. 湿度偏离个人目标超过 10% 时，提出湿度调节任务；
5. 未越过阈值时不执行设备动作。

除上述可逆且范围受限的照明 reflex 外，所有自治任务与交互任务共用语义解析、知识检索、规划、协作、安全审查、执行和反馈路径。reflex 不是通用设备控制捷径，也不能操作温控、门窗或安全规则。

同一房间的同类触发默认有 30 秒冷却期，并且只有动作成功后才开始冷却；失败动作会在下一周期重试并计入连续失败。用户手动控制灯光、空调、风扇或窗户后，对应房间和触发类型会获得 300 秒临时覆盖，期间自治不会立刻反转用户意图。服务连续失败 3 次会自动停机；生活快速仿真与常驻自治互斥；生活快速仿真运行时，状态重置、环境、设备、自然语言控制、画像、私有属性和鲁棒性配置等外部变更均返回 409。停止请求发出后，状态先进入 `stopping`；正在运行的 Agent 周期结束后才真正变为未激活，期间禁止启动第二个工作线程和执行依赖“自治已停止”的操作。

住户级后端环境是房间占用、设备和仿真时间的唯一事实来源。首次加载时前端从后端占用房间恢复人物位置；位置变更写回 `PUT /api/presence/current-room`，失败时界面回滚到后端确认位置。普通读取接口不会借读取之名推进时间或刷新天气；住户运行时创建时只同步一次实时时间和天气，后续时间仅由明确的仿真步骤推进。

API 鉴权、限流和 CORS 仍覆盖自治接口；CORS 位于最外层，因此 401/429 等保护性响应也能被浏览器读取并呈现为真实错误。功能回归使用独立的高限额配置，限流阈值本身应由单独的安全与负载测试验证。

接口：

```text
POST /api/autonomy/start
GET  /api/autonomy/status
POST /api/autonomy/stop
POST /api/autonomy/tick   # 停止状态下的单周期诊断
```

请求体示例：

```json
{
  "interval_seconds": 5,
  "simulation_minutes_per_cycle": 5,
  "repeated_trigger_cooldown_seconds": 30,
  "max_consecutive_failures": 3
}
```

## 用户私有知识库

浏览器首次访问时生成本地住户空间标识并保存在 `localStorage`，后续请求通过 `X-Simulation-Session` 发送该标识。每个标识对应独立的本地记忆和自治配置：

```text
data/private_memory/<session-id>/user_memory.json
data/private_memory/<session-id>/autonomy_config.json
```

该目录默认被 Git 忽略。记忆内容包括：

- 用户偏好画像；
- 用户主动填写的长期属性；
- 显式满意度反馈历史；
- 每次交互或自治决策后的反思记录；
- 按“意图 + 房间”聚合的成功、失败、完成率与证据量置信度；
- 显式反馈对最近一次反思的确认或纠正状态。

当前只有明确的怕风、避免直吹或浅睡表达会通过确定性映射进入规划约束：限制风扇为不高于 30%、阻止明显开窗，并把制冷设定下限保持在 26°C。其他自由文本只保存并展示，不会被系统擅自解释为健康诊断或控制规则。

相关接口：

```text
GET /api/research/private-memory
PUT /api/research/private-memory/attributes
DELETE /api/research/private-memory
```

写入长期属性的请求示例：

```json
{
  "attributes": {
    "health_constraints": "怕风，不能直吹",
    "sleep_and_routine": "夜间浅睡，23:00 入睡",
    "resident_notes": "在家办公，优先舒适度"
  }
}
```

属性值设为 `null` 可删除对应字段。清除整个私有知识库必须提交显式确认字符串 `RESET_PRIVATE_MEMORY`，并会重置画像、属性、反馈、反思和学习经验。

## 反思与演化边界

本项目把“自我进化”实现为可审计、受约束的持续适应，而不是允许模型自行修改程序或安全规则。

- 自治结果只更新经验统计和反思历史；
- 温度、照度等关键偏好只能通过用户显式反馈或画像编辑更新；
- 画像编辑也只有在私有记忆持久化成功后才提交；写入失败会保持运行中控制目标不变；
- 私有属性编辑也只有在私有记忆持久化成功后才提交；写入失败会保持当前安全约束不变；
- 显式反馈只有在私有记忆持久化成功后才提交；写入失败会回滚画像、反馈历史、反思关联和经验模式，不会在响应失败后暗中改变自治目标；
- 私有记忆清除也采用相同提交语义；若清除写入失败，运行中的画像、属性、反馈、反思和经验模式均保持不变；
- 满意度反馈会绑定到最近一次反思；同类情境至少得到 3 次显式反馈且正向比例达到 0.67，才标记为 `user_confirmed_pattern`；
- 只有 `user_confirmed_pattern` 会作为后续同类 Agent 规划的 `confirmed_experience` 上下文；它不改变温度/照度目标、设备动作模板或任何安全边界；
- 反思永远不能放宽安全规则；
- 单次失败不会直接改写用户画像；
- 若反思记录因本地私有记忆持久化失败而无法写入，已完成的设备控制仍保持成功；响应与黑板会标记 `recorded=false, reason=persistence_failed`，内存中的反思和经验模式会原子回滚，且该周期不更新经验统计、不触发重复控制或故障停机；
- 生活快速仿真的事件 CSV 同时保留 `reflection_recorded` 与 `reflection_reason`，用于区分已持久化经验、持久化降级和未产生反思，不能只根据控制成功率推断学习已完成；
- 置信度只描述同类仿真观察数量，不代表真实家庭中的正确率或安全概率。

未配置 `PRIVATE_MEMORY_ENCRYPTION_KEY` 时，本地开发仍使用明文 JSON，便于兼容已有数据；配置有效 Fernet 密钥后，新写入使用认证加密封装，已有明文文件会在下一次显式写入时迁移。加密文件缺少密钥或认证失败时会 fail closed，拒绝以默认画像覆盖不可读住户数据。Docker 把 `data/private_memory/` 挂载到宿主持久目录，避免容器重建造成隐式数据丢失。

这仍不等于完整隐私合规：密钥必须在仓库外生成、轮换和托管；`localStorage` 标识不是身份认证；当前也没有细粒度授权、备份密钥治理、合规导出、多设备同步或安全擦除证明。公开部署前必须运行 `scripts/validate_deployment_config.py deploy/backend.env`，并结合真实身份、同意、保留和删除流程评审。

## 证据边界

自治感知与反思闭环当前运行在软件数字孪生环境中。测试能够证明后端无浏览器调度、触发优先级、重复触发冷却、连续失败停机、住户空间隔离、配置/记忆重载和反馈确认策略的确定性行为，不能证明真实传感器可靠性、真实住户满意度、实体设备安全性、实际节能率或长期偏好学习有效性。上述结论仍需独立的真实设备与住户研究协议。
